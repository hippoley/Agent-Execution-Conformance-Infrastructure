# Primary User Story — First AgentPanel Vertical Slice

## Business outcome

> As an authorized business user, when I ask a managed Agent to set a supported low-risk device state, I need the action to be checked against trusted device identity, capability and permission, executed only within that scope, and reported with independently attributable state evidence, so that a tool or cloud ACK is never confused with physical completion.

**Acceptance:** One real AgentScope tool invocation reaches a separate fake-device service, then an approved test Tuya/ESP32 device; wrong device, expired action, unsupported capability and invalid arguments are blocked; lost ACK and unreadable state are reported accurately; every run links request, decision, outcome and evidence. Real hardware requires its own safety gate.

**Failure:** The same simulator is both sole actor and sole independent observer; success is derived only from tool response, text generated by the model, or an in-memory state mutation.

## What we have

A local simulator and **10 public `agent-device-effect/0.3` vectors** test bounded state-setting semantics under a supplied test principal. AgentScope source v2.0.10 is committed as an exact ordinary-file snapshot on `main`; integration is still absent. No authenticated device, production isolation, external readback or independent adopter has passed acceptance.
