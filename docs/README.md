# Documentation Map

Read in this order:

1. [Product overview](PRODUCT_OVERVIEW.md) separates what runs today from the product hypothesis.
2. [Primary user story](USER_STORY.md) defines the first outcome and evidence gate; [story catalog](USER_STORIES.md) keeps the customer requirements and future acceptance criteria.
3. [Current implementation architecture](ARCHITECTURE.md) documents code ownership and limits of local evidence.
4. [Target integration architecture](target/INTEGRATION_ARCHITECTURE.md) preserves the detailed Managed Agents, AgentScope, TuyaOpen and ESP32 system view. It is a target, not a shipped system.
5. [Position review](POSITION_REVIEW.md) records comparison, falsifiers and ecosystem evidence.
6. [Source import record](SOURCE_MIGRATION.md), [import report](AGENTSCOPE_V2_0_10_IMPORT_REPORT.md), and [third-party notices](THIRD_PARTY.md) document AgentScope provenance.

The current architecture and the target architecture are intentionally separate. The product overview links to the target diagram instead of duplicating it. `USER_STORY.md` is the prioritized story and proof gate; `USER_STORIES.md` is the fuller customer requirements catalog.
