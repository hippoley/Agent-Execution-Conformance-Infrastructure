# Adapters

Adapters translate framework and device APIs into the shared AgentPanel contracts. The current device adapter test interface is [`contracts/device-adapter.md`](../contracts/device-adapter.md); the execution-trace contract is a future lifecycle profile, not yet exercised by a runner.

No framework or production device adapter ships yet. An AgentScope adapter should map its tool-call lifecycle to the device-command contract; a TuyaOpen adapter should map that contract to a real supported device path. Integration code must not modify the vendored source under `vendor/agentscope/`.


## Loopback test integration (2026-10-22)

- `fake-tuya-client.mjs`: Node client to the separately running *test-only* fake Tuya HTTP service. No live Tuya SDK or hardware.
- `agentscope_fake_tuya_tool.py`: AgentScope v2 `ToolBase` subclass exposing only boolean `on`. Tenant/device/token are bound by the adapter constructor, not generated by the model. Requires real AgentScope dependencies to instantiate and register with `Toolkit`; runtime invocation is **not yet verified**.
- Start the test service using `node runners/fake-tuya-service.mjs` and run `node --test runners/fake-tuya-integration.test.mjs`. See [evidence](../docs/audits/2026-10-22-fake-tuya-closure.md).

**Never expose the fake service or its test bearer token as a production authentication mechanism.**
